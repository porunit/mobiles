# ADR-0002: единый реальный источник котировок

## Статус
Принято (2026-06-24).

## Контекст
В эталоне `Investment-pp` цена доходила до клиента не из конвейера биржи, а из
самовыдуманных значений DB-сервиса (`MarketDataService.tick()`). Конвейер
C-драйвер → Go-receiver был тупиком: его никто не потреблял. Ktor-шлюз публиковал
заказы в очередь, которую никто не читал, и не был в docker-compose.

## Решение
Восстанавливаем реальную сквозную цепочку как единственный источник истины:
```
C-драйвер → Go-receiver → RabbitMQ(quotes.topic) → DB-сервис(consumer) → Redis/ClickHouse → шлюз → клиент
```
- DB-сервис **не выдумывает цены** — он консьюмер очереди `quotes.consume.q`
  (`[[rabbitmq-topic-exchange]]`).
- Go-receiver — **только producer** (читает `[[linux-char-device]]`).
- Шлюз **реально терминирует** запросы (passthrough в DB-сервис) и развёрнут в compose.
- Единый контракт API `/api/v1` для всех клиентов и сервисов.

## Последствия
- (+) Чинит главную архитектурную ошибку эталона — разорванную интеграцию.
- (+) Появляется осмысленная роль у драйвера, receiver, брокера и шлюза.
- (−) Нужен явный момент трансформации `QuoteTick → Quote` (в консьюмере DB-сервиса).
- Негативный тест «DB не выдумывает цены» закрепляет инвариант (драйвер выключен →
  `/quotes` не врёт).
