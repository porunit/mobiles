# ADR-0001: стек бэкенда

## Статус
Принято (2026-06-24).

## Контекст
Задание подразумевает Ktor + голый SQL + Redis как брокер. Эталон `Investment-pp`
реализовал DB-сервис на Spring Boot + JPA, а брокером взял RabbitMQ.

## Решение
Берём бэкенд **как в эталоне**: `4-db-service` на **Spring Boot 3 + Spring Data JPA**,
брокер — **RabbitMQ**, Redis — **только кэш**.

## Последствия
- (+) Быстрее разработка, богатая экосистема, авто-инструментирование OTel Java-agent.
- (+) Сохраняем сильную часть эталона — пессимистичную блокировку сделок
  (`[[pessimistic-locking]]`).
- (−) По разделу «соответствие стеку» это сознательное отклонение от Ktor + голый SQL.
  Компенсируем тем, что **чиним интеграцию**, которую эталон провалил
  (`[[adr-0002-real-quote-pipeline]]`) — а раздел архитектуры важнее.
- Шлюз `3-gateway` остаётся на **Ktor** (как требует задание для «микросервиса связи»).
