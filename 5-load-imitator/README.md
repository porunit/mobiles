# 5-load-imitator — имитатор нагрузки (Kotlin)

**Итерация 2.** Статус: **реализован и проверен** (smoke-прогон 150 клиентов / 30с
через шлюз: 1779 запросов, 0 ошибок, 328 сделок). Прогон на 10k — по методике ниже.

Имитирует до 10 000 виртуальных клиентов без GUI: случайные запросы к **шлюзу** по
каноническому контракту. Подтверждает заявленную нагрузку.

## Что делает
- Корутина на клиента, `SupervisorJob` (изоляция сбоев), плавный ramp-up.
- Взвешенный сценарий: чтение котировок 40% / портфель 20% / покупка 15% / продажа 15%
  / история 10%.
- Атомарные метрики: RPS, p50/p95/p99, доля ошибок, активные сессии. OTel-экспорт
  (сэмплинг трейсов ≤10% на прогоне 10k).
- Бьёт в шлюз (`API_BASE_URL=http://ktor-gateway:8080`), не в DB-сервис напрямую.
- Регистрирует клиентов как `sim_<n>@load.test`.

## Методика 10k
Прогон 1k → измерение → экстраполяция к 10k; тюнинг пула Hikari и `max_connections`
Postgres; фиксация стенда (CPU/RAM) в отчёте. Это бенчмарк, а не «ноутбук держит 10k
вживую». См. `[[pessimistic-locking]]` (узкое место — пул соединений).

## ENV
`API_BASE_URL` · `CLIENTS` · `RAMP_UP_SECONDS` · `DURATION_SECONDS` ·
`THINK_MIN_MS`/`THINK_MAX_MS` · `HTTP_CONCURRENCY` · `METRICS_INTERVAL_SECONDS` · `OTEL_*`.
